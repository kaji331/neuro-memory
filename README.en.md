## 💡 Why You Need It

You've probably noticed: **large language models are brilliant, but also quite "forgetful."**

- They have no long-term personal memory — every session starts from zero;
- Once a conversation ends or you switch windows, previous info just *evaporates*;
- You keep re-explaining the same context, wasting both tokens and patience.

**neuro-memory is like giving your AI a "second brain":** it sinks valuable conversation knowledge, manages it scientifically with a forgetting curve, and retrieves it precisely when needed. Everything you need, it remembers.

---

## 🎯 What It Does

It silently performs two actions on **every conversation turn**:

### 📥 Before Responding — Retrieval
Before each response, it searches the memory store for past memories relevant to the current topic and injects them into context. **Silent by default** — it never interrupts you, yet quietly shapes every answer.

### 📤 After Responding — Recording
After each turn, it spawns a **background** sub-agent that:
1. **Summarizes** the turn into 1–2 sentences;
2. **Classifies** it into a three-tier "category → subcategory" hierarchy (fully dynamic, generated by the LLM — no predefined taxonomy);
3. **Scores** relevance (0.0 – 1.0);
4. **Stores** it into the memory store.

### 🧠 Three Core Features

| Feature | Description |
| --- | --- |
| **Three-Tier Smart Classification** | Categories, subcategories, and memory entries — all generated dynamically by an LLM, no predefined taxonomy |
| **Ebbinghaus Forgetting Curve** | Memories decay naturally over time; frequently "reinforced" memories last longer (default half-life: 24h) |
| **5,000-Entry Hard Cap** | Automatically prunes low-relevance old memories at the cap, keeping the store lean |

> 🎁 **Bonus: Silent Mode (on by default).** Memory retrieval and storage run entirely in the "background" — the AI never reveals it queried memory, for a seamless, natural experience. Want it "shown"? Set `silent` to `false` in the config.

## 🔌 Hook It Into Your Agents (opencode / Pi / Claude Code / Crush)

> This skill is designed to be **cross-agent** — the same `~/.agents/skills/neuro-memory` is distributed to different tools.

### opencode

Drop the skill into opencode's skills directory and it's auto-discovered:

```bash
ln -s "$(pwd)" ~/.agents/skills/neuro-memory
```

**How it works**: opencode scans `~/.agents/skills/*/SKILL.md` on startup and injects matching skills into the system prompt. SKILL.md tells the agent to query memory before each response and record after each response.

### Pi (π)

Pi discovers skills through `~/.pi/agent/skills/` (a symlink farm pointing at `~/.agents/skills/`):

```bash
ln -s ~/.agents/skills/neuro-memory ~/.pi/agent/skills/neuro-memory
```

> Already linked? Verify: `ls -la ~/.pi/agent/skills/neuro-memory`

### Claude Code

Claude Code loads skills from `~/.claude/skills/`. It **does not follow symlinks**, so create a copy:

```bash
cp -r ~/.agents/skills/neuro-memory ~/.claude/skills/neuro-memory
```

### Crush

Crush loads skills from `~/.config/crush/skills/` (also a symlink farm):

```bash
mkdir -p ~/.config/crush/skills
ln -s ~/.agents/skills/neuro-memory ~/.config/crush/skills/neuro-memory
```

### ✅ Verify Installation

```bash
ls -d ~/.agents/skills/neuro-memory 2>/dev/null && echo "✅ opencode"
ls -d ~/.pi/agent/skills/neuro-memory 2>/dev/null && echo "✅ Pi"
ls -d ~/.claude/skills/neuro-memory 2>/dev/null && echo "✅ Claude Code"
ls -d ~/.config/crush/skills/neuro-memory 2>/dev/null && echo "✅ Crush"
```

## ⚡ Update with a Single Command (bunx)

> Code got updated? **One bunx command** syncs the latest version into `~/.agents/skills`.

```bash
# Sync the latest skill to ~/.agents/skills/neuro-memory (preserves your data/ store)
bunx --bun -p "github:kaji331/neuro-memory" neuro-memory update

# Or: preview first, without writing anything (dry run)
bunx --bun -p "github:kaji331/neuro-memory" neuro-memory update --dry-run
```

Supported flags:

| Flag | Purpose |
| --- | --- |
| `--dry-run` | Preview what would be synced, without writing |
| `--force` | Skip the safety check (refuses by default if the target lacks `data/`) |
| `--target <path>` | Override install target (defaults to `~/.agents/skills/neuro-memory`) |

> 🛡️ **It's safe**: only syncs `SKILL.md`, config, `src/`, `test/` and other source files — it **never overwrites the `data/` memory database**.

## 💬 Using It in Conversation

During a chat, type `/memories` or `/memory` to manage your memories (these commands **always** print their results, regardless of silent mode):

| Command | Purpose |
| --- | --- |
| `/memory status` | Memory store overview (totals, categories, relevance distribution) |
| `/memory query <keyword>` | Search memories by keyword |
| `/memory recent` | Show recent memories |
| `/memory top` | Show highest-relevance memories |
| `/memory categories` | Show the category list |
| `/memory help` | Show available commands |

Unknown subcommands (e.g. `/memory delete`)? It will show the help list rather than guessing and running a nonexistent command. 👍

## 🔧 Configuration

Everything is configured through `neuro-memory.yaml` and takes effect immediately (these are all defaults; tweak as you like):

```yaml
# ── Silent mode (remember that "bonus" from the intro?) ──
silent: true                    # true = fully silent (default); false = print retrieved "past memories"

# ── Database ──
db:
  type: sqlite                  # sqlite | postgres | duckdb | mysql | mariadb
  sqlite_path: "~/.agents/skills/neuro-memory/data/memory.db"
  # postgres_url: "postgres://user:pass@localhost:5432/neuro_memory"   # postgres only

# ── Memory Limits ──
memory:
  max_entries: 5000                   # Hard cap on memory entries (100-100000)
  max_token_per_entry: 1024            # Max tokens per entry summary (256-4096)
  max_categories: 50                   # Max top-level categories (10-500)
  max_subcategories_per_category: 100  # Max subcategories per category (10-500)
  max_subcategory_links: 3             # Categories a subcategory can link to (1-10, many-to-many)
  max_subcategory_per_memory: 10       # Subcategories a memory can belong to (1-20)

# ── Retrieval ──
retrieval:
  relevance_threshold: 0.75     # Minimum relevance to retrieve (0.0-1.0, higher = stricter)
  max_results: 3                # Max memories fetched per query (1-10)
  timeout_ms: 3000              # Retrieval timeout in ms; skip injection if exceeded

# ── Forgetting Curve (Ebbinghaus) ──
ebbinghaus:
  half_life_hours: 24           # Half-life: time for relevance to drop to 50% (hours)
  min_relevance: 0.1            # Below this, memories are auto-pruned during maintenance
  reinforcement_boost: 0.15     # Boost applied each time a duplicate "reinforces"
  prune_interval_hours: 1.0     # Interval between automatic pruning runs (hours)

# ── Summarization / Classification ──
summarization:
  model: ""                     # Empty = use the same model as the main agent
  prompt_template: ""           # Empty = use the built-in default prompt
```

**Config resolution order**: `--config <path>` flag → `$CLAUDE_SKILL_DIR/neuro-memory.yaml` → `./neuro-memory.yaml` (cwd) → the defaults above.

## 🧰 CLI Commands at a Glance

> Invoke with `bun run src/cli.ts <command>`, or use the installed `neuro-memory` command directly.

### 🔍 query — Search memories

```bash
bun run src/cli.ts query --keyword "python"          # by keyword
bun run src/cli.ts query --category "programming"    # by category
bun run src/cli.ts query --all --limit 20            # everything (most-recent first)
bun run src/cli.ts query --relevance 0.8 --limit 5   # by relevance (top)
```

> 💡 **New capability**: `--all` lists everything, sorted **newest-first**; with no filter at all it defaults to `--all` (great as a "recent memories" listing).

### ➕ insert — Insert a memory

```bash
# Mode 1: give the content directly
bun run src/cli.ts insert \
  --content "TypeScript is a typed superset of JavaScript" \
  --summary "TypeScript definition" \
  --category "programming" \
  --subcategory "languages" \
  --relevance 0.9

# Mode 2: bulk import from a JSON file
bun run src/cli.ts insert --from-file memories.json

# Mode 3: inject a snippet of conversation text (placeholder, goes to "Unclassified/General")
bun run src/cli.ts insert --conversation-turn "<conversation text>"
```

> 🔁 **Auto-dedup**: identical content triggers a "reinforce" instead of a duplicate insert (prints `Memory already exists. Reinforcement applied (+1).`).

### 💪 reinforce — Reinforce a memory

```bash
bun run src/cli.ts reinforce --id 42               # by ID
bun run src/cli.ts reinforce --content-hash <prefix>  # by content hash
bun run src/cli.ts reinforce --all                 # everything
```

### 🧹 prune — Prune low-relevance memories

```bash
bun run src/cli.ts prune --dry-run   # preview what would be deleted
bun run src/cli.ts prune --force     # confirm and run
```

### 📊 status — System overview

```bash
bun run src/cli.ts status
```

### 🔄 maintenance — Full maintenance (recalculate relevance → prune → orphan cleanup)

```bash
bun run src/cli.ts maintenance
bun run src/cli.ts maintenance --force
```

### ✅ validate — Validate configuration

```bash
bun run src/cli.ts validate
bun run src/cli.ts validate --show-defaults   # print the default config
bun run src/cli.ts validate --file path/to/config.yaml
```

## 🧩 How It Works

```
User Message
    │
    ▼
┌─────────────────────────────────┐
│ opencode / Pi / Claude / Crush  │
│ (reads SKILL.md every turn)      │
└─────────┬───────────────────────┘
          │
    ┌─────┴─────┐
    │           │
    ▼           ▼
 Retrieval     Recording
(BEFORE)      (AFTER)
    │           │
    │           ▼
    │  task(run_in_background=true)  ← background sub-agent
    │  ┌──────────────────────────┐
    │  │ summarize → classify →  │
    │  │ score → store            │
    │  └──────────────────────────┘
    │
    ▼
┌──────────────────────┐
│  neuro-memory CLI    │
│  src/cli.ts          │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  DBAdapter           │
│  (SQLite / Postgres) │
│                      │
│  Core tables:        │
│  categories          │
│  subcategories       │
│  memories            │
│                      │
│  + Ebbinghaus decay  │
│  + 5000-entry cap    │
└──────────────────────┘
```

## 💾 Database Support

| Backend | Status | Notes |
| --- | --- | --- |
| **SQLite** | ✅ Full implementation | Built on `bun:sqlite`, incl. forgetting-curve SQL and `:memory:` support |
| **PostgreSQL** | ✅ Full implementation | `pg` connection pool, 3 retries; requires installing the `pg` dependency |
| **DuckDB** | ⛔ Stub | Throws "not implemented yet" |
| **MySQL** | ⛔ Stub | Throws "not implemented yet" |
| **MariaDB** | ⛔ Stub | Throws "not implemented yet" |

> 📌 **Decoupled and portable**: at its core is a clean `DBAdapter` interface + factory — adding a new database is just implementing another adapter.
